# Architecture Review: obsidian-summairize

## Overall Impression

Small (~760 lines of TypeScript) Obsidian plugin with clean separation of concerns across services, utils, UI, and settings modules. Code is readable and the folder structure is logical. However, there are several significant deficiencies.

---

## Major Deficiencies

### 1. No Tests

No test framework configured, no test files, no test script in `package.json`. The `NoteUtils` class (summary insertion, extraction, content validation) and `FileFilter` are particularly testable and particularly dangerous to leave untested.

### 2. Duplicated Exclusion Logic

`getExclusionReason()` in `main.ts:102-128` reimplements the same template and daily-note detection that `FileFilter.isExcludedFile()` already does. If filter rules change in `FileFilter`, the reason messages in `main.ts` will silently drift out of sync. The exclusion reason should be returned by `FileFilter` itself.

### 3. AIProvider Naming Collision

`src/types/index.ts:17` defines an `AIProvider` **interface**, and `src/services/AIProvider.ts:3` defines an `AIProvider` **abstract class** with the same name but different shapes. The interface is never imported or used anywhere. This is confusing and will mislead anyone extending the provider system.

### 4. Fragile Summary Insertion/Replacement

`NoteUtils.insertSummary()` (`NoteUtils.ts:2-29`) has problems:
- When an existing `# Summary` section is found, it inserts a *new* sub-section rather than *replacing* the old one. Running the command twice produces duplicate `## Generated by AI` blocks.
- The regex `\n(?=# [^#])` matches the `# Original Article` heading that `insertSummary` itself inserts, leading to unpredictable insert positions.
- `extractContentForSummary` uses a different regex than `insertSummary` to detect summaries, so they can disagree on summary boundaries.

### 5. User-Supplied Regex Without Sanitization (ReDoS)

`FileFilter.ts:43` and `main.ts:117` compile user-supplied `dailyNotesPattern` directly into `new RegExp()`. A malformed pattern can cause catastrophic backtracking and freeze the UI. There is also no `try/catch` around `RegExp` construction, so an invalid regex throws an unhandled exception.

### 6. No Request Timeout or Cancellation

`OpenAICompatibleProvider.ts:31-47` — `fetch()` calls have no `AbortController` timeout. If the API endpoint hangs, the plugin blocks indefinitely. The `isAvailable()` pre-check also has no timeout. No way for the user to cancel a pending request.

### 7. No Concurrency Guard

Nothing prevents the user from clicking the ribbon icon multiple times rapidly. Concurrent `generateSummaryForActiveNote()` calls would both read the file, both generate summaries, and both write back — producing corrupted or doubled output.

---

## Moderate Deficiencies

### 8. innerHTML XSS Pattern

`SettingsManager.ts:182-189` uses `innerHTML` to render status. While the interpolated values are currently safe, this establishes an unsafe pattern. Obsidian's `createEl`/`createDiv` API should be used instead.

### 9. No Debounce on Settings Saves

Every settings `onChange` handler fires `updateSetting` → `saveData` on each keystroke. Typing a URL fires dozens of disk writes and `aiService.updateSettings()` calls with no debounce.

### 10. Hardcoded 8000-Character Truncation

`NoteUtils.truncateForAI` hardcodes 8000 characters as a proxy for token limits. Characters ≠ tokens (~4:1 for English). Different models have different context windows. Should be configurable.

### 11. Dead CSS

`styles.css:54-55` uses `:contains()` which was never adopted as a CSS standard. The rule does nothing.

---

## Minor Issues

- **Unused imports**: `main.ts:1` imports `Modal`, `PluginSettingTab`, `Setting` but never uses them.
- **Placeholder author**: `manifest.json` and `package.json` have `"author": "Your Name"`.
- **ESLint packages with no config**: `@typescript-eslint/*` in devDependencies but no `.eslintrc` and no `lint` script.
- **Non-reproducible builds**: `obsidian: "latest"` and no committed `package-lock.json`.
- **Outdated dependencies**: TypeScript 4.7.4 (current 5.x), `@types/node` ^16 (current 20+).
- **`console.log` in production**: `main.ts:50,54` and `OpenAICompatibleProvider.ts:74`.

---

## Recommended Priority

1. Add test suite for `NoteUtils` and `FileFilter`
2. Fix summary insertion to replace rather than duplicate
3. Add timeout + concurrency guard to API call path
4. Consolidate duplicated exclusion logic into `FileFilter`
5. Resolve `AIProvider` naming collision
6. Sanitize user-supplied regex
7. Add debounce to settings handlers
8. Pin `obsidian` dependency version and commit lockfile
